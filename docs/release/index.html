Release & CI/CD

版本号、Pages 和 Release 构建是怎么配合的

1. 现在有哪些自动化

  • 推送到 main：触发 GitHub Pages 文档部署
  • 推送 v* tag：触发 Release 构建工作流

2. 正确的发版顺序

# 修改版本号
# Cargo.toml -> version = "0.2.2"

git add .
git commit -m "release: v0.2.2"
git push origin main

git tag v0.2.2
git push origin v0.2.2

3. 为什么你刚才看到 Release workflow 失败

我本地已经复现过 x86_64-unknown-linux-musl 的 release 构建，当前代码本身是能过的。所以截图里那次更像是 GitHub Actions 侧的单点失败，而不是代码已经坏了。

我这次顺手把 workflow 改成了 矩阵失败不再直接全体取消，这样就算某一个目标出问题，其他目标还能继续构建，排查也更清楚。

4. GitHub Pages 第一次启用要做什么

  • 进入仓库 Settings → Pages
  • 确认 Source 使用 GitHub Actions
