Getting Started

第一次部署 XzBot，照这页一步一步来

本页目录

1. 你需要准备什么

  • Rust stable 工具链
  • NapCat
  • 一台能稳定运行机器人的机器
  • 至少一个可用模型网关（先用 mock 也可以）
如果你现在只想先把链路打通，不要急着接真实模型。先用 mock 跑通，会省很多时间。

2. 如何编译

git clone https://github.com/XiNian-dada/XzBot.git
cd XzBot
cargo build --release

编译完成后，主程序通常在：

./target/release/xzbot

3. 第一次运行会发生什么

./target/release/xzbot

首次运行时，它会在二进制所在目录自动生成：

config/config.toml
config/owner.toml
config/server.toml
config/policy.toml
config/group.toml
config/persona.toml
config/ai.toml
config/search.toml
config/network.toml
config/web_admin.toml

这些覆盖文件默认是关闭的，也就是顶层会有：

enabled = false

4. 最小可用配置

只想先把机器人跑起来，先改主配置：

# config/config.toml
[owner]
qq = 你的QQ号

[group]
whitelist = [允许触发机器人的群号]
trigger_mode = "at"

[ai]
provider = "mock"

这样它先不会真正访问模型 API，但消息链路是可验证的。

5. 怎么确认链路通了

  1. NapCat 配好反向 WebSocket 后，启动 XzBot。
  2. 看 XzBot 控制台里是否出现监听日志。
  3. 在白名单群里 @机器人 说一句最简单的话。
  4. 如果它有回应，就说明 OneBot → 路由 → 回复链路已经通了。
如果出现 Address in use，说明旧进程还占着端口。先停旧进程，或者换 server.port。
