把 XzBot 当成一个“能聊天、能搜、能看图、能扩展”的宿主平台来用。

XzBot 不是一个只会“你说一句、它回一句”的简单 QQ 机器人。它已经具备了多模型接入、函数调用工具、图片与文件上下文、插件宿主平台、网页控制台、外部推送 API、最近群聊工具化上下文等能力。 这份文档会带你从零开始把它部署起来，并且把常见配置、常见坑和升级路径讲明白。

一句话理解

它是什么？

XzBot 是一个运行在你自己服务器上的 QQ 机器人运行时。NapCat 负责把 QQ 消息转成 OneBot 事件，XzBot 负责做路由、上下文、LLM 调用、插件扩展和管理面板。

最适合谁

谁该用它？

想自己掌控机器人逻辑、模型 API、搜索/OCR/代理配置，并且希望后面能继续写插件扩展能力的人，都会很适合这套架构。

别先担心的事

你不需要先会什么？

你不需要先会 Rust 开发，也不需要先懂插件协议。先按这份文档把机器人跑起来，后面再慢慢加功能就行。

Step 0

准备工作

在正式部署前，请先准备好下面这些东西：

  • 一台能稳定运行 NapCat 和 XzBot 的机器。Linux 最推荐，macOS 也可用于开发和打包。
  • Rust 工具链（建议 stable）。
  • NapCat，并且知道如何进入它的 OneBot v11 配置页面。
  • 至少一个可用的模型 API 网关（OpenAI 兼容或 Anthropic 兼容）。
  • 如果你要图片 OCR：本地 Tesseract，或者一个可用的 Paddle OCR HTTP API。
最保守的跑通方式是：先把 [ai].provider 配成 mock，确认 NapCat 和 XzBot 能正常收发消息，再换成真实模型 API。
Step 1

从零部署：最快能跑通的方式

1. 克隆并编译

git clone https://github.com/XiNian-dada/XzBot.git
cd XzBot
cargo build --release

2. 启动一次，让它自动生成配置模板

./target/release/xzbot

首次运行时，程序会在二进制所在目录自动生成：

config/config.toml
config/owner.toml
config/server.toml
config/policy.toml
config/group.toml
config/persona.toml
config/ai.toml
config/search.toml
config/network.toml
config/web_admin.toml

这些覆盖文件默认都带 enabled = false，不启用就不会生效。

3. 最少要改哪几个配置？

只想先跑起来的话，先改 config/config.toml 里的这几块就够了：

[owner]
qq = 你的QQ号

[group]
whitelist = [允许触发机器人的群号]

[ai]
provider = "mock"

4. 重新启动

./target/release/xzbot
如果终端里已经提示 Address in use，说明这个端口上已经有一个 XzBot 在跑。先停掉旧进程再启动新的。
Step 2

NapCat 应该怎么配

这个项目只用 NapCat 的 OneBot v11 反向 WebSocket（WS 客户端）。也就是：

  • NapCat 主动连 XzBot
  • XzBot 自己作为 WebSocket 服务端监听

在 NapCat 里，连接地址填：

ws://你的服务器IP:3000/onebot/v11/ws

如果你开启了 token 校验，就在 NapCat 的反向 WS 配置里把 token 一起填上。

配置项 推荐值 说明
OneBot v11 开启 这是协议基础，不开就没有事件。
WS 客户端 / 反向 WebSocket 开启 这是 XzBot 的标准接入方式。
WS 服务端 可关闭 除非你还有别的系统依赖它。
HTTP 上报 可关闭 XzBot 本身不依赖 HTTP 上报。
Step 3

配置文件怎么理解：主配置 + 可选覆盖

这套配置设计的目标很简单：

  1. 大多数人只改一个 config/config.toml 就能跑。
  2. 真正复杂、很长、很少改的部分，再拆到覆盖文件里。

最推荐的思路

  • 日常只改 config/config.toml
  • 当某一块内容太长，再把它拆到 persona.toml / ai.toml / network.toml
  • 把那份覆盖文件的顶层 enabled 改成 true

一个例子

比如你想把超长人设单独拿出去：

# config/persona.toml
enabled = true

[persona]
system = """
这里放一大段人设
"""

[[persona.group_overrides]]
groups = [970199915]
system = """
这个群用另一套人设
"""

升级时旧配置会怎样？

如果你是从老版本的单文件配置升级，XzBot 会在发现旧的 ./config.toml 时，自动把它结构化迁移到新的 config/ 目录里。

迁移不是简单复制，而是会把 persona / ai / search / network 这些大块自动拆到各自的覆盖文件里，这样迁移完成后的主配置会更轻，更适合继续维护。
能力清单

常用功能怎么用

模型与回退

XzBot 支持同一 provider / base_url / api_key 下的多模型回退。主模型失败后，会自动尝试候补模型：

[ai]
provider = "openai_compatible"
base_url = "https://your-gateway.example/v1"
api_key = "sk-xxx"
model = "gpt-5.4"
fallback_models = ["gpt-4.1", "gpt-4o-mini"]

OpenAI Responses API

[ai]
provider = "openai_compatible"
base_url = "https://your-gateway.example/v1"
wire_api = "responses"
api_key = "YOUR_API_KEY"
model = "gpt-5.4"

Chat Completions 流式兼容

有些兼容网关只有 stream=true 才稳定返回正文，这时可以加：

[ai]
wire_api = "chat_completions"
stream_chat_completions = true

搜索 / 抓取 / 天气

  • search_web：搜索网页
  • fetch_url：抓网页内容。知乎会优先走公开 API。
  • get_weather：天气兜底工具。长天气优先靠搜索和网页预览。

图片与文件

  • 多模态模型会直接看图
  • 纯文本模型会走 OCR 兜底
  • 普通文本文件会自动提取内容
  • docx 会尝试提取 OOXML 里的正文文本
  • 引用消息、转发消息、最近群聊工具里都可以把图片/文件一起带进上下文
内置运维面板

网页控制台：不想手改 TOML 时，直接用它

控制台和机器人本体共用同一个 HTTP 服务，不需要额外端口。开启方法：

[web_admin]
enabled = true
token = "请换成你自己的强随机 token"
title = "XzBot Console"

访问地址：

http://你的服务器IP:3000/admin

控制台当前能做这些事：

  • 登录鉴权
  • 查看当前模型、Provider、WS 在线状态
  • 编辑主配置和覆盖文件
  • 查看最近日志，而且日志页支持自动刷新
  • 查看插件列表、命令、事件订阅、工具
  • 在“插件”页用文件管理器方式浏览并编辑插件文本文件
  • 保存后直接触发热重载
如果你修改了 server.host / server.port / server.ws_path 这类监听项，控制台会提示你“需要重启进程后完全生效”。这不是 bug，是因为监听套接字本身不能只靠运行时热重载就完全重绑。
扩展系统

插件系统：把新功能尽量放进插件，不要继续堆主程序

XzBot 现在的插件系统已经不是“只能响应 /命令”的轻量壳了，它更像一个宿主平台：

  • 命令型插件
  • 事件型插件（订阅群消息、私聊、mention、图片、引用等）
  • 工具型插件（把插件工具注册给 AI 的 function call）
  • 多动作输出（先发文件，再发文字）
  • stop_propagation 阻断默认 AI 处理

插件目录长什么样？

Plugins/
  MyPlugin
  MyPlugin-plugin/
    plugin.json
    config.toml
    state.json
    output/
      ...

建议怎么扩展功能？

  1. 公共运行时能力进主程序
  2. 业务功能尽量进插件
  3. 插件自己的配置和缓存文件放自己目录，不污染主配置

插件开发细节仍建议结合仓库里的开发文档和现有插件样例一起看。

升级、版本号和 GitHub Actions 发版

当前版本

本次文档更新同时把 crate 版本提升到 0.2.0。

仓库现在有两条自动化链路

  • 在线文档：推送到 main 后，GitHub Pages 自动部署 docs/ 目录
  • Release 构建：推送形如 v0.2.0 的 tag 后，GitHub Actions 自动构建并发布 release 附件

如果你要发布新版本，推荐顺序

# 1. 修改版本号
# Cargo.toml -> version = "0.2.0"

# 2. 提交并推送主分支
git add .
git commit -m "release: v0.2.0"
git push origin main

# 3. 打 tag，触发 Release workflow
git tag v0.2.0
git push origin v0.2.0
如果你的仓库第一次启用 GitHub Pages，请到仓库设置里确认 Pages 来源使用 GitHub Actions。启用后，文档地址通常会是：https://你的用户名.github.io/XzBot/
常见问题

FAQ：最容易卡住的地方

1. 启动时报 Address in use

说明端口已经被旧进程占用。先停掉旧进程，或者换 server.port。

2. Bot 不回消息

  • 先看 NapCat 的反向 WS 是否真的连上了
  • 再看群是否在白名单里
  • 再看触发模式是不是 @ / 前缀 / 关键词

3. 网页控制台打不开

  • 确认 [web_admin].enabled = true
  • 确认你访问的是正确端口
  • 确认运行的是包含控制台代码的新二进制

4. 某些兼容网关只在 curl 下能用，Bot 却报空内容

这通常不是你配置错了，而是网关只在 stream=true 下稳定返回正文。可以尝试：

[ai]
wire_api = "chat_completions"
stream_chat_completions = true

5. 为什么有时看不到群里前一个人的问题？

现在最近群聊上下文已经改成了按需查询工具，模型需要时会主动取最近群消息。但如果你想让它最稳地理解“前一个人说了什么”，最好还是直接引用那条消息。
