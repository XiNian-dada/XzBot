XzBot 使用说明

这不是宣传页，而是一份按普通使用流程整理的文档：首页先告诉你它能做什么，再带你把机器人跑起来，然后说明怎么配置、怎么接 NapCat、怎么日常维护。

适合第一次接触项目的用户，也适合后面只想快速查路径和命令的人。

项目概览

XzBot 是一个基于 Rust + Tokio + Axum 的 QQ 机器人宿主，使用 NapCat 的 OneBot v11 反向 WebSocket 接入。它能处理群消息、调用 LLM、做图片 OCR、走网页搜索，也能把功能拆成插件扩展出去。

  • 消息接入走反向 WebSocket，不需要你自己暴露额外的公网回调。
  • LLM 后端支持 OpenAI 兼容、Anthropic 兼容和 Mock。
  • 图片理解和 OCR 都已经接到主流程里了。
  • 插件系统、网页控制台、外部推送接口都已经在运行时里。

如果你只想先验证链路，先把 [ai].provider 设成 mock，最省时间。

先把它跑起来

依赖只有 Rust 1.75+ 和 NapCat。最短路径如下：

cargo build --release
./target/release/xzbot

程序会从可执行文件所在目录读取配置，默认主配置是 ./config/config.toml。首次启动时会自动生成模板，后续你主要改这个目录下的文件。

如果你还没准备真实模型，先用 mock 跑通消息链路，再换成正式网关。

NapCat 怎么接

XzBot 使用的是 OneBot v11 反向 WebSocket。也就是说，是 NapCat 主动连过来，不是 XzBot 去推给它。

ws://<主机IP>:3000/onebot/v11/ws

其中 3000 来自 [server].port，/onebot/v11/ws 来自 [server].ws_path。如果你打开了 token 校验，两边填同一个值即可。

配置文件怎么理解

默认布局是“一个主配置 + 多个可选覆盖文件”。普通用户通常只需要改 config/config.toml；如果某一块变长了，再拆到单独的覆盖文件里，例如 persona.toml、ai.toml、search.toml、network.toml。

覆盖文件默认都关闭，顶层会有 enabled = false。想让它生效，就把它改成 true。

# config/config.toml
[owner]
qq = 123456789

[group]
whitelist = [123456789]
trigger_mode = "at"

[ai]
provider = "mock"

代码里也支持旧版单文件配置迁移，但新项目还是建议按目录结构来，后面更好维护。

日常使用看什么

XzBot 的日常行为比较直接：

  • 触发方式支持 @、前缀和关键词，具体看 [group].trigger_mode。
  • 上下文目前是内存存储，重启后会清空。
  • 内置工具包括网页搜索、URL 抓取、系统信息、进程信息和天气查询。
  • 权限模式支持 None、OwnerOnly 和 Whitelist。
  • 运行时命令包括 /reset、/blacklist、/reload、/log、/posttoken。

如果你发现机器人没回复，先看这三件事：群是否在白名单里、触发方式是否设置对、模型网关是否真的可用。

控制台和外部接口

程序还提供了网页控制台和外部推送接口。控制台默认挂在 /admin，是否启用和 token 由 [web_admin] 管。外部 POST 推送接口是 /api/post/send，用于把文本、图片或文件发到指定会话。

如果你更想少改配置、多看状态，控制台会比直接手工编辑 TOML 轻松很多。

插件系统

插件目录在项目运行目录下的 Plugins/。当前实现已经不只是简单命令壳，还支持事件订阅和工具注册，所以后续新增能力尽量优先做成插件。

插件最适合放这三类东西：命令、事件处理和给 AI 暴露的新工具。

常见问题

  • 如果提示 Address in use，先停掉旧进程，或者换一个端口。
  • 如果 NapCat 连不上，优先检查地址、端口和 token 是否一致。
  • 如果模型一直失败，先用 mock 验证链路，再换真实网关。
  • 如果看不到群消息，先检查白名单和触发模式，不要先怀疑 AI。
